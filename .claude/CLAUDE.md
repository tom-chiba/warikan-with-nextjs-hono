# プロダクト方針

- 夫婦など固定メンバーで一度作ったグループを長く使うことが前提。飲み会のような単発グループは主ターゲットではない
- メイン機能は購入品入力。日々の入力を手軽にする改善を優先すること
- 以下は検討のうえ不要と判断済み。再提案しないこと
  - アカウントなしの仮メンバー機能
  - グループの貸し借りサマリ（ダッシュボード）
- 等分割の端数を乱数で振り分ける現仕様は、長期利用で統計的に均されるため問題なしと判断済み

# パフォーマンス方針

- 購入品入力（ルート `/` のクイック入力と `/groups/[groupId]/items/new`）は日常的に最も高頻度で開かれる画面。常に軽く・高速に開ける状態を維持すること
- ルートページや `ItemForm` 周辺に依存・リクエスト・重い処理を追加する際は、初期表示までの往復回数とバンドルサイズへの影響を確認してから行うこと

# 作業の進め方

- こまめに git commit すること
- コードベースの修正を入れる際には必ず新たにブランチを切ってから作業を行うこと
- main ブランチへの直接 push はせず、 PR を出してレビューしてからマージすること
- push 前の修正分に関しては amend や rebase も活用して過去の commit を改変し、 Git tree をきれいに保つこと
